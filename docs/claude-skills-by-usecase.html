運用モデル: メインセッション = 司令塔（仕様・レビュー・意思決定）。実行はバックグラウンド subagent / worktree にファンアウトし、 成果物（diff + 検証 + 推奨）をレビューする。スループットはタイピング速度ではなくレビュー帯域から生まれる。

朝の一括投入— 稼働開始時、タスクが溜まっているとき

/batch
  1. 前夜〜朝に ~/.claude/batch/inbox.md にタスクを書き溜める（1 行 1 タスクで雑に OK）
  2. /batch — 各タスクの spec contract（成果物形式・完了条件）を整えてから案件ごとに background subagent へ投入
  3. ユーザーは離席。各 worker は branch + diff + 検証 + 推奨を用意して待つ（publish はしない）
  4. レビュータイムにまとめて確認 → 採否判断 → /batch publish <task>

未報告のクライアントセッションも /batch が surfacing してくれる（unreported.md）。

学習サイクル— 個人リポジトリ・学習時間

/mode/learn-map/learn-coach/learn/reflect

切替基準は「時間と場所」: 仕事 = Speed（デフォルト）、学習時間（個人リポジトリ・~/learn）= /mode learning（答えを書かない・地図を渡す）。「Speed」で復帰。役割分担 — /mode learning = セッションの構え / /learn-map = 教材生成 / /learn-coach = 演習中の専門コーチ（ヒント段階制が優先）。仕事中に協働スタイルにしたいときはモードではなく「骨格は自分で書く」等のその場指示で。

  1. Before: /learn-map — GUIDE.md + 演習問題 + STRUGGLE_LOG.md を生成（答えは絶対に出さない）
  2. During: 詰まったら /learn-coach — ヒントは L1 言語化 → L2 視線誘導 → L3 一次情報 → L4 答え の段階制。L4 はギブアップ宣言か 30 分格闘後のみ
  3. After: /reflect（振り返り）・/learn（再利用パターンを skill 化）

Speed モード中の「Learning flag」で積まれたトピックを、時間のあるときに /learn-map で回収する設計。
